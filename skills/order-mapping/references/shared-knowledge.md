# 共享知识与原文执行契约

共享表达结构规则`explicit_attribute_order`只在基础品名和全部明确属性完全一致后归一前后置；类别标签须与当前目录类别一致，括号“斤”须与当前500g计价基础一致。它不推包装转换，不通用移动单字“鲜”或“干”，也不把“冷冻干燥/冻干”等复合工艺拆成冷冻属性。未知词、品牌、加工、部位、大小和包装仍保留。该有限语法通过合成开发和反例回归，不代表自然语言已穷尽；宿主Agent仍须主动语义核对。

正式默认知识为`knowledge/procurement.json`；公司特殊约定为`knowledge/company-contracts.json`。每条规则有id、稳定concept、aliases、selector、conditions、evidence、applicable、conflicts和validation_status。`general/conditional`仅在原文条件满足后用于自动身份选择；`candidate_only`只能补候选，不能自动定SKU。历史审阅状态不代表未见订单验证。

当前知识版本19包含93条共享概念规则、2条单位规则和1条受限表达结构规则。证据区分目录明确同义、历史对照、语言推断和独立目录名称审阅；语言推断不等于供应商或用户确认。新增干制/鲜带盐海带及鲽鱼、百合、鱿鱼的语序别名均限定在同一基础名和全部属性约束内，不能移动单字“干/鲜”或跨形态替代。规则中的自然语言`conflicts`供审阅，不是逐条可执行断言；匹配器及宿主Agent共同检查商品名与数量后的备注中的品牌、部位、鲜冻、熟制、加工及规格。未证明原文要求的冷冻/熟制/鲜活、加工履约或计价基准时不得自动计价。单位条件不满足时，同义概念仍可用于检索候选；不能用已知品名推定袋盒罐净重。包装条件候选规则只在指定单位上下文生效，不能覆盖正常按重量的明确需求。选择层与候选检索层分别审计；同规则别名的新品名称按同类目重新检索并转人工，不静默沿用旧首选。`conditional`描述规则需要满足商品、目录或上下文约束；`conditions`为空不表示存在额外结构化条件，仍须按现有选择器、属性约束及审阅边界执行。

目录同一记录在名称中以斜杠直接列出两个完整商品名时，匹配器只把这两个名称作为该记录的受约束互标候选；括号内的`净含量/包装单位`不是互标。若同名独立记录与互标记录同时存在且规格不同，保留候选并转人工。规格变更时重新校验名称明示净含量、选择层和单位规则，不能沿用旧包装换算。

维护时逐条区分同义词、条件经验、一次调整、冲突和替代。共享selector用商品规范名、类别或明确属性，不存材料编号、旧价和实际称重。已知普通品名对应普通目录项时优先最接近原文；不能把老黄瓜、新土豆、油豆角等变成通用同义词。品牌未指定且商品、形态、包装和计价基础等价时，按当前最高挂牌价排序；规格、单位或商品仍不唯一时保留所有合理候选。


KB7普通需求复核：干豆腐先选择普通整品，排除切丝/卷/扣及加厚；两条普通500g记录按当前价比较。蒜薹/蒜苔可检索蒜苔（绿帽），甘蓝/大头菜由目录斜线直接互标；明确其他品种不套用。海天上等耗油按错字识别为同品牌同上等系列，瓶需求由当前目录明确的1kg/瓶核量；其他系列和箱装关系仍未决。玉米粒罐头只比较普通原味罐装的同规格候选，不用冻袋装或不同规格替代。香蕉的优质/优选当前没有量化等级差别，普通整果同500g称重可比较；明确品牌/加工/大小要求仍须逐项满足。以上为目录及用户价格规则支持的需求选择，不把不同品牌宣称为同一种叫法；选择过程与当前候选、价格一起留痕。目录改规格变得不可比时停用自动选择，不能沿用本次结果。
目录激活后按selector重新解析当前记录，价格和名称规格取同一记录。每批保存knowledge SHA与selector可用性审计。下架、改名或规格变化导致无候选或不可比较时停用该选择；不从v1快照补SKU。名称选择器遇重命名可能转人工，这是需维护的知识失效，不是继续套旧名的授权。计价量仅用当前规格或正式包装规则，历史同数量不证明换算。

特殊约定必须包含company_id、`evidence.kind=user_confirmed_contract`、source、locator及具备相同证据字段的concept规则。默认`shared`不叠加公司合同，必须显式选择`shared_with_company_contract`。当前文件为空：历史人工表不足以证明公司已确认特殊约定。因此shared_with_company_contract当前应与shared相同，消融报告不得虚构增益；旧公司profile仅在显式`legacy_profile`模式用于历史回放。

原文`run-messages`只接受schema_version、batch_id、chat_files、config、shipping_date、company（可选批次上下文）、matching_mode（默认shared）、test_only和discount。`config.companies`给公司全称和认可简称；不会根据文件名、评测manifest或人工行号分单。无公司依据进入“归属待核”订单，金额空。日期必须由使用者明确完整批次日期；文本明确日期可分日，部分日期与批次相距半年以上时须核年份。

控制事件只按可核关系处理：“再追加2斤”为增量；“总量改为4斤”须保留并替代全部已知前项；“取消”不生成新的采购金额。明确重复转发只有与紧邻前项的公司、日期、品名、数量和单位一致时才可确认为重发。关系不唯一、部分取消、区间/备选数量、缺单位的改量均保持待核。零量、负量、非法分数和无法识别的数量也逐条保留，不能整批退出、静默取第一个数或当作免费。

结构化`run`允许本批Agent语义审阅。自动结果错误或候选遗漏时可提供：

```json
{"candidate_reviews":{"本次解析line_id":{"catalog_version":"当前版本SHA","raw_text_sha256":"本次raw_text UTF8 SHA256","confirmed_by":"agent","reason":"具体歧义和排除依据","candidate_codes":["当前材料编号"],"candidate_reasons":{"当前材料编号":"适配和待核差异"}}}}
```

它撤销选品并按当前目录完整展示候选，不会产生金额。可以显式给空候选，表示目录确实无合理项。逐项`decisions`用于本次主动语义选择，须绑定当前目录、理由和约束先行最高价声明；只能用户有据确认覆盖计价数量。不能注入评测预期或批量复用旧决策充当新识别。

验证时A=自动且所有业务字段正确/自动完成；B=同一正确数/所有输入；C=自动正确+确应人工且处置正确/所有输入。未知正确答案保持undefined，不能自动改成“确应人工”来提高C。修改、取消和被替代行保留总账与去向，不能当有效采购量。未定义控制预期不得宣称其语义完全通过。评测代码和答案不属于技能运行依赖。


KB8普通前缀：只在已审阅的基础概念内支持“普通”表达，不通用删除品牌、品种、加工等词。目录解析兼容合法XLSX缺工作表dimension元数据，不改上传文件；注册、校验、更新仍绑定原始文件指纹。

KB9普通需求复核：下五花肉用目录直接指定下五花的普通整品层，去皮下五花只在原文有去皮要求时另核；泛称五花、精五花不等同指定下五花。普通红肠与粉肠分别在同品同500g、没有原文明示品牌限制的直接名称记录中比较当前挂牌价，风味项和其他肠类不自动跨层；这属于满足泛称需求的选择，不宣称不同品牌是同义词。普通木耳优先直接基础品名“优质木耳”，不因黑山秋/小木耳价格高而省略其额外品种大小描述。下五花、上五花、小木耳及品牌/加工词若写在备注也须有目录正面证据；未知数量或包装不造数、不计金额。新目录改名、下架或可比规格失效仍转人工。审阅证据是原文和当前目录，未使用人工SKU本身证明同义或替代。


KB10去皮下五花条件：原文或备注明确去皮时，普通下五花规则由notes_excludes退出；独立notes_contains去皮规则检索当前明确“冷鲜去皮下五花（金锣）”。该目录名直接证明部位与去皮，500g与斤可换算，原文没有品牌/鲜冻限制时可以自动计价。切片等额外需求和指定品牌仍单独约束。没有去皮要求时不进入该条件层；当前目录缺少去皮项则保留异常，不能回退已确认普通下五花。conditions的notes_contains/notes_excludes同样检查原始片段，用于条件选择，不删备注或猜数量。


KB11否定与带皮边界：去皮条件规则不适用于“不要去皮”“不去皮”或“带皮”；普通下五花层也不自动证明带皮，以上表达保留待核，不从未写带皮的目录名猜皮是否保留。此局部边界不代表已覆盖所有否定或复杂语义，宿主Agent仍应语义审阅。

KB12北极冰虾条件：当前目录有同品种、同80*100数字规格的冷冻项。原文未限定鲜活或非冷冻时，可以动态选择该项并保留“冷冻”描述；明确鲜活、拒绝冷冻、品牌或不同数字规格不能被省略。斤/kg等质量按当前计价基础重算；目录500g改为250g或1kg时重新换算，袋/箱或未知规格不推净重。原项下架或改名后须重新解析，不能沿用旧SKU或价格。生腰果仁是否去壳仍缺商品证据，只供候选。此次否定保护为列举条件，不代表全部自然语言已覆盖。

rc8控制提示修复：已解析的独立尾部加工备注“不要去皮”不因“不要”被标为订单取消；同文另有明确取消、追加或改量仍按事件核定。仅在已验证的表达和位置适用，其他表述由宿主Agent继续语义审阅。

KB14指定品牌参考：当“某牌商品”没有品牌已证候选时，当前目录中基础商品名称完全一致且不含其他已知品牌的记录作为品牌未证参考展示，不能自动选中、换算或计价。粉/粒等不同形态不由此扩张；明确其他品牌仍排除。本条不依赖已审别名、公司或历史答案，新目录下动态检索。普通尖椒规则收敛为原文未限产地时比较同500g普通/地产鲜尖椒当前价，红色与明确其他品种另核，避免规则文字与选择器相互矛盾。

KB16新增受限概念的逐条来源、排除近邻和证据边界见[受限概念审阅](kb16-reviewed-concepts.md)。新增四个目录商品经过开发修复后已参与知识提炼，不再作为未见商品成绩。


KB17关系表达：共享 `expression_rules.relations` 记录连接词、属性标签、上下文前缀和形态词的证据边界。基础名要/按属性时，仅将完整基础名与完整属性分别组合，再对当前目录完整名称校验；品种/等级/产地/形态标签不能证明原文未写的属性。“干制/干品”只规范显式干形态；不移动未标明的单字“干”。多种组成对应不同商品（如干豆腐/豆腐干）保留全部候选，最高价不能解决商品含义歧义。进口、清真、冰鲜等属性须在当前目录名称中明确，包装、未知词、否定和加工动作不得删去。规格/备注约束先筛选，再在等价同计价基础候选比较当前价；不得用高价优先覆盖明确规格。规则不绑定目录行号或旧价。验证状态为本地合成开发与回归，不代表真实新订单或供应商资质确认。

数量说明如“商品，订购数量待确认/订购2”属于同一原始商品事件，缺失字段保留异常。数量后出现“要求/备注/要/按”的其他数值作为要求中的规格处理，不能覆盖前述明确下单量；同一说明内的有机、鲜冻等非数值属性仍须核对。无独立下单量的“切片、去骨、别要肥的”等尾部限定保留在前项备注；明确新商品及其数量仍拆为独立事件。切段、磨成粉与现成商品的形态不同，不能用粉状商品价格证明加工履约和加工后计价量；原量保留，未确认金额为空。复杂指代和未列出的自然语言依然需要本批Agent语义审阅。


KB18完整关系结构：支持“基础品名的属性款”“要属性的基础品名”“基础品名，要求属性”。这是语言结构的有条件归一，不是跨商品替代。连接词仅在完整结构中移除，基础名及全部属性必须组成同一条当前目录商品名称；未知品牌、特选/大小、加工及包装词不能丢弃，否定表达不自动归一。多个组成对应不同商品时保留全部候选；同属性商品再按符合规格的等价层比较当前价格。目录更新后重算，不缓存旧SKU或旧价。验证为合成开发与独立反例，不代表全部自然语言或真实新增订单。

“商品，要求冷冻3斤”将要求和量保留在同一原文事件；已存在明确下单量时，后面的规格量不能覆盖下单量。数量前置并有规格要求时保留前置数量，规格留在备注，不能把500g规格当成订购500g。完整span用于工作簿批注和人工审核。

KB18控制链：文字不同但同一当前商品的表达，在含改量/取消的批次中先通过同一正式匹配器证明商品身份，再在公司与日期范围内关联前项；无法证明时不能用词面相似合并。关系不唯一时相关行和控制行pending，计价量、标准订单金额与财务金额为空，原始数量单位保留。“刚才改”“刚才那条不要了”只表明控制意图，不能证明指代唯一。身份缓存保留普通原文约束；未新增外部调用。


KB19选择与供货结构：显式“选属性的商品”“商品请按属性供货”“属性商品要”及数量后的同类备注，仅删除已配置语法连接，所有商品和属性词必须完整组成当前目录同一记录；未知词、品牌、否定、加工、包装或多个不同组成继续待核。备注约束校验同步识别选择与供货语法，不把“选”误当商品属性。显式尾部“规格500g”从商品词面移至备注并由当前目录尺寸验证；规格量不充当下单量，基础名缺少鲜冻等区分属性时不补猜。控制身份未证的同名需求不允许通过同义追加保留旧金额。该版本仍只证明本地已执行的规则/原文回归；候选语义全集、完整Agent及真实宿主未穷尽。
