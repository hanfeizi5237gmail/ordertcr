# v4 交叉核验验收口径与风险审查

状态：`analysis`。本文是 v4 验收口径和阻塞清单，不是主设计文档，也不是新的运行时实现基线。主设计仍以 [`../../ordertcr/设计方案.md`](../设计方案.md) 为准；v3 结果是历史参考回归，不能改称未见订单准确率。

## 已确认的证据边界

- v3 报告的主身份指标为 127/132（96.21%）。159 是三站全部聊天事件（松北 53、星月 42、学院 64）；其中 155 是聊天—人工表对齐事件，132 是 v2 延续的“当前目录可核人工商品事件”。155 是事件对齐数，不是互不重复的人工表行数；一个人工行可能对齐多个事件。v3 对照口径另有 127/155（81.94%）和 127/159（79.87%），后两者均为该 127 个一致事件在更大事件总体中的覆盖比例，不是所有事件均具有可判定 SKU 真值的准确率。
- 三站人工表不是逐聊天事件的独立真值。已读人工表显示星月人工行 31 将“豆角 5 斤”和“油豆角 6 斤”合为油豆角 11.2 斤，行 35 将两条菜花 6 斤合为青梗菜花 12.2 斤；人工表还有实配量、价格和当前目录不存在的品牌/商品。`manual_row` 到聊天事件不是普遍一对一关系。
- `evaluate_v3.py` 的 review 断言可验证原始片段跨度、台账字段、部分工作簿元数据、身份/异常候选、金额空值和批注标色；`source_quantity_correct` 的含义应保持为“台账数量字段与 review 字段一致”，数量真值的独立性仍依赖 review 的来源。`decisions.json` 与 `review.json` 的生成独立性也没有机器证明。
- 订单技能明确要求按公司隔离 profile，保留追加/取消/改量及疑似重复事件，禁止无依据把条/颗/根/筐/袋等换算成重量或整包；人工数量恰好相同不足以证明包装关系。见 [`skills/order-mapping/SKILL.md`](../skills/order-mapping/SKILL.md) 和 [`skills/order-mapping/references/business-rules.md`](../skills/order-mapping/references/business-rules.md)。

## v4 必须先定义的评估对象

每条样本要同时保存 `canonical_event_id`、原始 `line_id`/字符区间、来源站点、评估时声明的目标公司、原始数量/单位、商品身份状态、数量状态、异常类型和候选集合。拆分重组用于 v4 的变形回归，不等于训练/测试独立切分。若将来另做留出评估，最小单位是**原始事件依赖组**，不是拆分后的 token 或 Excel 行；同一事件的分隔符变体、重复运行、修订链、同一人工行关联的多个事件和所有派生输出必须在同一折内。

建议将 v4 分为三类，不能合并成一个“交叉准确率”：

1. **语义不变性回归**：同一公司、同一目录和同一原始事件的逗号/顿号/空格/换行/全角数字等变体。答案可定义为 canonical 事件集合、原文覆盖和身份/异常状态不变；数量只在规则明确时比较，不能用人工实配量作为变体真值。
2. **同公司留出回归**：按原始事件组分层留出 profile 学习集和评估集。评估集中的人工答案只有在事件与人工行可一对一、商品仍在当前目录、且没有人工合并/跨日/实配换算疑点时才可作为 `exact_identity` 期望；其余只能作为约束、候选集或“答案未定义”记录。
3. **跨站/跨公司组合**：保留每个事件的真实来源公司，分别加载该公司 profile；可以组合输入顺序、来源站和未见事件以测隔离与路由。将事件重新标为另一公司是反事实测试，原站人工 SKU 不再是目标公司的金标准；若无目标公司独立人工答案或用户确认，期望应为“不能定义精确 SKU”，只能验品牌/品种约束、无偏好时的通用规则、候选完整性和待人工状态。

三站只有三个来源时，可做 leave-one-station-out 的泛化报告，但必须写明训练 profile 的站点、留出站点和是否允许通用目录规则；不能把留出站人工表先注册成 profile 后再称跨站泛化。

## 公司偏好与跨站污染防线

- profile 适用键至少包括 `company_id + normalized_name + original_unit + catalog_sha`，决策、候选和结果必须记录实际命中的 profile 来源。站点 A 的“豆角→架豆王”不能在站点 B 直接成为答案，除非 B 有独立偏好证据；无品牌泛称可共享语义原则，不能共享具体 SKU 偏好。
- 评估前冻结 profile、目录版本和 decisions 的哈希。若另做留出评估，训练/参考侧只使用训练事实生成 profile，测试侧不得读取测试人工答案来补 alias、unit rule、decisions 或异常答案；完整人工表作为同一份文件提供注册指纹时，哈希只能证明文件一致，不能证明 profile 未使用留出事实，须逐条记录可审计的训练来源和排除证据。若发现测试答案参与注册，该折标记 `leakage`、报告原始计数，不得计为有效留出准确率。
- 跨站混合后的总体分数必须按公司分层报告，并追加“profile 命中公司正确率”“无 profile/通用规则正确率”“跨站偏好污染数”。任一事件使用了别站 SKU 偏好、旧价、实配量或行号，判隔离失败，即使最终 SKU 与人工表碰巧相同。

## 事件、重复行和数量合并

- 没有“再加/改成/取消”等动作的重复原文必须保留为独立事件；不同日期也不能静默合并。合并只能由可追溯的明确关联或用户确认产生，并保存 `merged_from`、合并理由和数量依据。
- 一个人工行对应多个聊天事件时，人工总量不能复制到每个事件。商品身份可在证据足够时作为事件级候选；实配数量、包装换算和金额应为 `undefined/needs_review`，除非存在独立逐事件拆分依据。
- v4 需要单独统计：事件保留率、重复/追加/取消关系准确率、误合并数、误拆分数、人工行多事件数、人工行无法唯一反投影数。误合并或误删任一原始事件是阻塞级错误，不得用商品命中抵消。

## 分隔符变化与源事件回溯

- 合成分隔符变体须带 canonical-to-variant 映射。`raw_text` 的字节/字符跨度不能要求与变体相同，但事件 ID、原始片段覆盖、数量/单位边界、来源引用和输出行数应可回溯到 canonical 事件。
- 追加、改量、取消和替换要按事件链验收：最新有效状态、被取消事件、关联依据和变更时间都应保留。不能只比较最终商品表而忽略被取消或被修改的源事件。
- 随机拆包可能把日期标题、站点上下文、前序指代或修订对象与事件拆开。必须以可核的来源映射恢复实际上下文；不能从文件名猜日期，也不能凭空补全“这样的”等指代。无法恢复时应标记上下文缺失和人工待核，而非机械继承原结果并算通过。
- 回放输出应能反查 `source_file/source_line/char_start/char_end`，并证明没有因分隔符或排序变化丢失非空片段。无法解析的片段必须进入异常集合，不能从分母删除。

## 异常处理的可定义答案

异常期望不能只写“没有误选 SKU”。对每个异常事件，冻结：`expected_candidate_codes`（筛选后完整合理候选集合，可为空）、`required_issue_codes`、原始商品名/数量/单位、待决原因和批注要求。验收分别报告：

- 候选集合精确率/召回率（集合相等或按审核允许的集合关系）；
- issue code 精确率/召回率；
- 原文、数量、单位和来源回溯完整率；
- 异常颜色、原生批注、未知价格/金额留空率；
- 异常未被静默选 SKU、未被删除、未进入完整金额总额的比例。

`expected_codes=[]` 只有在 `expected_exception_reason` 非空且理由、候选和 issue 均独立冻结时才是可验答案；“selected is None”单独不能证明异常处理正确。

## 建议的 v4 指标与固定分母

所有指标都同时输出 `numerator/denominator`、站点/公司分层和 `undefined` 数，不允许把 undefined 静默改成错误或从分母删除：

| 指标 | 分母 | 通过要求/解释 |
|---|---:|---|
| `source_event_coverage` | 全部原始事件 159（或 v4 明确的新事件清单） | 159 个事件均有来源、canonical ID、解析状态和输出去向；缺失即阻塞 |
| `identity_exact_132` | 冻结的 132 个目录可核人工事件 | 只用于与 v3/v2 的可比回归；不得扩成未见准确率 |
| `identity_coverage_155` | 冻结的 155 个聊天—人工对齐事件 | 以可核人工 SKU 一致事件为分子；目录外等未命中依然在分母中，v3 为 127/155 |
| `identity_coverage_159` | 冻结的全部 159 个聊天事件 | 以相同的可核人工 SKU 一致事件为分子；未对齐事件也保留，v3 为 127/159 |
| `identity_exact_defined` | 留出集中有独立、唯一、目录内商品真值的事件 | 只在答案可定义时计分，另报 undefined 数和原因 |
| `accepted_candidate_or_exception` | 全部 159 | 商品命中、完整候选异常、或有依据的保守待核均以冻结 oracle 审阅；不可判定者列 `undefined`，不得冒充通过 |
| `exception_candidate_set_exact` | 独立冻结异常事件 | 候选集合和 issue 均符合；不能仅以未选 SKU 计通过 |
| `quantity_status_accuracy` | 有独立数量/包装真值的事件 | 商品身份与数量状态分开；未知包装不能因人工同量变成 matched |
| `source_preservation` | 全部原始事件/片段 | 原文、数量、单位、来源和变更链完整；重复/取消不静默丢失 |
| `profile_isolation` | 触发 profile 的事件 | 命中 profile 的公司和目录版本正确，跨站污染为 0 |
| `denominator_reconciliation` | 每站 53/42/64、总 159；身份另 132 | 各子集加总等于总数；禁止结果驱动剔除分母 |
| `amount_safety` | 全部输出行 | 未知数量/价格/异常金额为空且不进完整总额；可计价行金额可复算 |

`identity_exact_132` 应保留 v3 的 127/132 作为历史回归对照；v4 新增的留出或跨站指标必须另起分母和标签。建议不要设置一个加权总分掩盖某站失败，至少同时给出宏平均、微平均、每站结果及最差站结果。

## 阻塞项（完成前不得宣称 v4 交叉验收通过）

1. **人工答案可定义性未冻结**：没有逐事件 oracle/约束/undefined 分类表，尤其是人工行合并、目录外商品、跨日和包装实配疑点；阻塞所有随机拆分准确率。
2. **目标公司语义未冻结**：跨站重分配事件没有目标公司独立偏好或用户确认；若仍使用原站人工 SKU 评分，属于偏好污染。
3. **profile/decision 来源不可追溯**：当前变形回归须记录实际使用的 profile、目录和 decisions 指纹及公司归属，不能直接把 review oracle 变成运行时答案。历史样本参与 profile 拟合时仍可验收变形回归，但不能宣称盲测或跨站泛化；只有另行主张留出准确率时，训练/测试分离及其证据才是该主张的额外阻塞项。
4. **事件级拆分与回溯未实现或未复核**：无法证明变体、重复、追加、取消和合并没有跨折泄漏或丢行。
5. **异常 oracle 不完整**：候选集合、issue、原因和批注未独立冻结；仅检查 `selected is None` 不足以通过。
6. **数量与金额口径未分离**：人工实配量或“聊天数量相同”被用于跨事件回填、包装换算或缩小分母；该行为应直接判定数量安全失败。
7. **分母账本不守恒**：报告未同时列 132、159、各站总数及 undefined/异常/合并子集，或通过删除难例、未输出行、异常行来提升百分比。

## 当前结论

现有材料足以支持 v3 的历史参考回归和对 v4 风险的静态审查；不足以支持“随机拆分后人工答案仍普遍可定义”或“跨站组合准确率”。当前 v4 验收仍待实际执行并提供冻结 oracle、profile 隔离、事件与来源追溯及分母账本的证据。该判断不否定已通过的本地语义/分隔符变形回归；现有拟合 profile 可用于历史变形回归，但不能替代独立客户样本。
