# 学院路人工表与聊天：准确率与差异审计

结论：**现有材料不能证明未来订单达到95%准确率。** [v2样本回归](v2_accuracy.json) 的目录内商品身份为53/53，但 profile 正是从这份人工表学习，属于参考样本拟合；人工表还包含配送实称、增删和旧价格，不能直接当作聊天需求的唯一正确答案。本审计可按 [JSON统计](xueyuan_accuracy_audit.json) 及 [逐行证据](xueyuan_regression.json) 复核。原聊天、人工表和目录均以 SHA-256 绑定；脚本为 `audit_xueyuan_accuracy.py`。

|比较项|观察数|分母如何确定|意义与限制|
|---|---:|---|---|
|原始聊天与人工有明确顺序锚点|62|64条聊天、63条人工商品行|聊天58、64行无人工对应；人工64行蒜瓣无聊天来源，不能把这些错算成解析失败或默默补单|
|人工名称与聊天解析品名不同|42/62（67.74%）|逐一对齐的62项|包含规范名称、品牌补全、规格/部位描述；不等于42次品牌错误|

“品牌改名”没有可靠的单一错误率分母：已对齐62行中，名称不完全一致42行，但例如“海天鲜生抽→海天酱油鲜味生抽”保留品牌，“红肠→农大红肠”是在原文未指定品牌时增加采购偏好。应逐行标注原文明确品牌、规格、包装约束是否保留，再统计冲突数，不能把任何名称差异自动视为品牌替代，也不能用人工选择反向证明该选择安全。目录外或名称规格未唯一定位的9个对齐项不进入SKU身份准确率分母，同时必须在覆盖率与未决清单中保留。

95%验收应使用**profile 未训练过的新日期、新批次**，由业务人员对原文、目录版本和实际处置逐项独立标注：商品身份在“当前目录确有唯一可核正确SKU、需求约束明确”的行上统计命中数/合格行数，并同时披露目录覆盖率、自动选择率、未决率和错误自动选择率；所有原始项目及取消/合并事件必须逐项可追溯。数量另设需求解析率和已确认实称计价率：在没有实称证据时保留原需求与未决，不能要求其数值等于人工配送量。价格核对必须绑定当前目录版本、折扣及输出舍入策略；正式财务还需逐项实际配送、税运与收货日期的业务验收。预设决策门槛可采用独立样本的SKU正确率≥95%、原始事件留存100%、无未经确认的品牌/包装替代；样本量、置信区间和例外处置须在试验前固定。当前没有这样的独立验证集、真实配送记录或导入回执，故只可称“历史参考拟合通过”，不能声称95%生产准确率。
