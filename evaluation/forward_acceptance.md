# 首次使用的最少交互验收标准

本清单用于让首次使用者按自然语言与真实文件做前向验收，不依赖某个脚本、Agent或界面实现。判断依据是可观察的问询、订单、批注和可追溯记录；演示配置与历史人工样单不算用户确认。真实公司、实称、财务税运和导入验收尚未提供时，应交付标识明确的复核件或草稿。

## 一次性初始化与本批提问

| 给使用者的情境 | 最少应收集或处理 | 验收时看到的行为 |
|---|---|---|
| 首次使用，没有保存的主体和价目表 | 一次集中询问公司标准全称、可用简称/别名及财务商户名，并请用户提供当前有效商品目录；用户可先只确认做需求订单所需的公司资料 | 配置能保存确认范围；公司未确认时可出有明确说明的复核件，但不能静默填示例公司或声称正式入账 |
| 首次订单 | 本批所属公司和明确的`YYYY-MM-DD`发货日期；文件名中的“11.3”不能代替用户确定年份或日期 | 同一已确认批次上下文可复用，不为每条商品重复问日期或公司；跨日聊天逐日保留并集中确认发货安排 |
| 目录已保存，后续再来一批且未提供新表 | 不要求重复上传同一目录 | 读取持久当前指针和快照，订单记录目录版本、来源文件、接收时间及SHA；重启会话后仍可读取同一状态。独立设备未携带状态时明确要求恢复/提供目录，不声称云端自动同步 |
| 明确提供新表更新 | 校验可读性、编号、规格和价格，成功后自动切当前版本；历史参考附件保持参考身份 | 同名内容变化建新版本，删去商品不从旧表补回；更新失败时标出问题并阻断按旧价继续产生看似最新的订单；多表更新顺序不明时只问哪份当前 |
| 订单号和正式发布 | 询问既有号段/最大号、多设备是否共用台账及编号策略；需求单或实绩单准备正式发布才需这些确认 | 预览及含异常复核件不消耗号码、编号格为空并解释；`publish`经确认且商品/数量/主体/日期/编号前提满足后，需求单可有正式OR号，但仍标“下单需求/待配送” |

可以先拿到用户当前愿意确定的公司、目录、发货日并产出复核件，再集中询问剩余阻塞项。避免逐商品询问所有可由明确约束得出结论的匹配，也避免为了初次预览强迫用户先完成实称、税运、财务价格和号段。

## 商品和单位的最低判断

1. 输入包含空格、逗号、换行、全角数字、小数或中文数词时，每个实际订货项目均有来源片段，日期标题和寒暄不作为商品。`5色糙米10斤`只能拆出10斤，`一品鲜酱油一桶`拆出1桶；跨日和重复条目保留原事件，不能无依据合并。
2. 候选先满足品牌、鲜熟、加工、包装、单位和规格，再在相同可比基础中选最高挂牌价。条件足以使某个SKU唯一且可计价时，Agent可记录自己的选择理由和目录版本，批次无需逐项打断用户确认；该决定不自动成为长期别名。多个真正不确定的候选仍进入异常行，在**原生批注**中列出全部合理候选及编号、目录名称、规格、挂牌价和行号。
3. `孜然粉2`、`萝卜丁咸菜大袋的`分别保留缺单位、缺数量；`火碱3斤`不能匹配为面碱。按条鲤鱼、按颗白菜、按筐鸡蛋遇到目录按斤计价时等待实称或明确包装依据，不编造重量或把缺失值写成0。
4. 异常商品同样进入十列标准订单：无匹配为浅红，多候选或数量/单位未决为浅黄；D列原生批注包含完整原句、来源、原因和待用户处理事项，未知G/I/J留空，合计仅为“已确认金额小计”。确认后重新计算并记录原始值和变更依据。若宿主不能写原生颜色和批注，必须说明该验收点未满足。

## 财务的最少交互

- 需求订单与实际配送分开：用户只给聊天时可制作“下单需求_待配送”订单和明确标“预估_待配送”的财务草稿；不能把需求数称为实绩或入账。
- 首次要正式财务时，集中询问并保存：实称/配货依据、收货日期意义和具体日期、财务价格来源、销售单位、折扣和舍入策略、含税/不含税及运费口径、商户名、财务订单号来源与OR/PL关系。若决定订单和财务用不同金额策略，另显示两种口径及尾差，不通过隐含调整平账。
- 未确认任一必需口径时，财务只出可识别草稿、缺项清单和已确认金额小计；未知税额不填0，10.31财务样例价格不自动沿用于11.3。正式财务须与标准订单来自同一已确认批次台账，未解决的异常商品不能作为零金额商品行混入。
- 多个已导出批次合并财务时，须逐份校验manifest、对应目录版本、配置及输出指纹；有缺失或版本不一致则拒绝把它们伪装为同一已确认账本。

验收记录至少写明用户是否提供/确认上述事实、目录版本和指纹、每项语义选择或异常依据、预览与正式发布的编号状态、所用金额策略、保存后订单批注/颜色复读结果，以及人工签收或系统导入是否执行。没有实际配送、财务用户确认和真实系统导入证据时，只报告已完成的需求/结构验证。
