# v2 独立复核（2026-11-07）

范围：只读检查 `profiles.py`、`matching.py`、`workflow.py`、`export.py`；在 `evaluation/tmp` 的独立运行目录重放测试批次。没有修改生产代码，也没有把参考人工表当作未来实配真值。

## 已复现并在本轮修复

1. **未决行进入 manifest 金额，和 Excel 小计不一致。** 原版 `workflow.py` 对需求数量先计算 `amount/finance_amount`，之后因缺逐项实配将状态改为 `needs_review`，但 manifest 金额仍汇总该值。修复前复现：`settlement + delivery_confirmed=True`，无逐项实称，行 `amount=1.9095`，manifest `standard=1.9095/finance=1.91`，两张工作簿小计却为0。主代理随后在 `status!=matched` 时清除金额并只汇总已匹配行，新增 `test_settlement_requires_per_line_actual_quantity` 回归；本代理重跑 `test_workflow.py`，8/8通过。真实财务导入仍未验证。
2. **历史别名的伪来源和秋林→农大错配曾通过入口。** 初始 `profiles.py` 只校验 SHA-256 形状、SKU 存在及证据非空，`matching.py` 曾直接应用错误品牌别名；原始只读复现中64个 `0` 的伪哈希及“秋林红肠→农大红肠”均被接受。主代理随后要求 `register_profile(..., source_path=真实文件)` / CLI `--source` 并验证文件 SHA，新增注册、运行时 alias 及逐项 decision 的显式品牌冲突防护。独立重试：伪哈希+真实文件注册被拒；不带 source_path 被拒；“秋林→农大”的 profile 校验被拒；强行传入此别名的 `match_item` 仅返回 `needs_review`，错误 decision 也仅返回 `needs_review`。松北 profile 带真实人工文件成功注册。`test_profiles.py` 7/7、`test_matching.py` 10/10、`test_workflow.py` 8/8通过；保护词表并非所有商品品牌的语义判断器，未来新品牌仍需人工核对。

## 仍需明确的发现

词表防护与来源 SHA 验证可以识别这些明确输入，但人工来源本身可能包含替代、改品牌或错误。`validate_profile()` 仍不能证明每一个“原品名→SKU”语义关系已获得未来批次授权。保留逐项证据和人工审阅，不能把注册成功等同于95%外推准确率。

## 已核对的行为

- 当前松北 profile 通过 `validate_profile()`，只含当前目录 SKU、原品名和原单位适用范围；未存历史订单数量、称重或价格。未登记“秋林→农大”、五色→七色糙米、袋装玉米粒→罐头等冲突。
- 初次隔离重放曾包含五条按人工数量相同拟合的包装规则；进一步复核发现豆腐、酸菜、鸡爪在目录只写重量，没有每盒/袋数量的独立证据，因此最终剔除三条单位规则，仅保留目录明确袋装的鸡柳与娃娃菜。最终计数以 `songbei_alignment.json` 和 profile 为准。
- 隔离重放的松北批次共 53 条；鲤鱼3条命中当前 SKU 后保留 `product_status=matched/quantity_status=needs_review`；工作簿该行 D/E=当前目录名称/规格，F=原量3且有原量未换算批注，G=14.99、I=14.2405、J 为空。没有把三条鲤鱼推断成重量或把历史实重复制进计算。
- `date_policy=by_date` 已在 `workflow.py` 标为待复核阻塞；正式 settlement 逐项实配缺失时也已转 `needs_review`。目录及 profile 版本参与批次指纹，过期 profile 不沿用。

以上仅是离线、样本内的规则核验；profile 本身从同一人工表拟合，不能用同表计算独立预测正确率。真实配送、税运、财务导入和跨日期业务确认仍需实际验收。

## 松北人工订单逐行对齐与 profile 取舍

`audit_songbei.py` 读取源聊天、人工表和目录，生成 `songbei_alignment.json`（53条聊天逐项对应）与 `songbei.history-profile.json`（35个原品名/原单位范围别名，2条有袋装证据的计件规则）。52条聊天找到人工行，聊天第3行“尖椒4斤”无人工对应；44个人工商品身份可在当前目录按名称+规格定位，但明确冲突或证据不足的不自动登记 profile。全体52条人工行有对应聊天事件，仍不能推断聊天独有项已取消。

主要剔除项：聊天32行明确“秋林红肠”而人工33行选农大，profile 不学农大替代；聊天48行“五色糙米”对应人工七色糙米，也不学2袋数量；聊天24行玉米粒2袋被人工填成罐头3罐，包装和数量均不一致。小黑茄子、下五花肉、厚皮鸡蛋、罗马生菜、豆角、牛肉卷等明确品种/品质/形态可能冲突，保留人工对照而不建立替代别名。烟桂、虾仁、大米、橘子、方便袋、胶皮手套、刷锅等人工商品不能唯一绑定当前目录的相同名称+规格SKU；色拉油的人工价73.9与当前SKU 65.9 不同，且原料身份没有确认，因此不覆盖价格或登记该别名。详细原因及聊天/人工行号见 alignment JSON 的 `exclusion` 字段。

豆腐7盒、酸菜4袋、鸡爪3袋虽然人工计价数量碰巧分别为7、4、3，目录仅有490g、750g、1kg重量规格，没有独立的盒/袋包装定义；因此只保留可能的SKU偏好，不学“一盒/袋=一个计价单位”，最终这些行商品已确定但数量待核。鸡柳 `800g/袋` 的2袋与人工2计价件、娃娃菜袋装的1包与人工1袋有商品包装和逐行计数双重依据，才限定松北公司和当前目录版登记1:1规则；仍不代表未来实际发货数。
